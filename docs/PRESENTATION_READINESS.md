## What's new since v2.5

The camera panel on `/dashboard` now shows a real, live annotated video
frame — boxes, class labels, confidence, anonymous track IDs, PPE state, and
the restricted/overhead-zone polygons burned into an actual decoded replay
frame — refreshed roughly once per second, not structured detection text
alone. See `docs/adr/0003-annotated-camera-frame-delivery.md`.

## Recommended demo sequence

Follow `docs/DEMO_SCRIPT.md` in full; abbreviated here:

1. `make demo`, open `/dashboard` — real backend data, no placeholders.
2. Point out the CO2 chart (physics + hybrid GRU forecast) and Time-to-Action.
3. Open `/simulation`, start `gradual_leak`, show the clock and controls
   feeding the same public ingestion path.
4. Back on `/dashboard`, show the camera panel's live annotated frame and the
   restricted-zone polygon.
5. Move the worker into the restricted/overhead zone; watch severity change
   with a stated reason code.
6. Open the incident drawer: evidence image, Acknowledge → Investigate →
   Resolve, audit history.
7. Download the JSON/CSV report for that incident.
8. Reload the page — incidents/evidence/audit persist.

## Known limitations to disclose if asked

- `no_helmet` recall is low (0.175 on the held-out test split) — the
  documented weak point of the v1.1 checkpoint; the v1.2 seven-epoch
  candidate was evaluated and rejected (see
  `docs/adr/0002-vision-v2-roadmap.md`, `models/registry.json`
  `rejected_experiments`) rather than promoted.
- The bundled interview clip's peak `no_helmet` confidence (~0.049) sits
  below the active 0.05 class threshold on that footage — the demonstrated
  helmet incident is generated by the "helmet not positively verified in the
  overhead region" policy path, not a direct `no_helmet` detection. State
  this plainly if the helmet incident comes up; do not describe it as a
  direct detection.
- Detection metrics are measured on construction-site imagery
  (Construction-PPE dataset), not a real factory floor — a disclosed
  synthetic/domain-to-real and construction-to-factory gap.
- This is a prototype, not certified for real industrial safety decisions.
- One `make interview-demo-e2e` run out of three hit an isolated console
  `409 Conflict` (a pre-existing simulation-command race under accelerated
  `speed=300`) that did not reproduce on immediate retry. If a console error
  appears live during the interview-demo path specifically, it is very
  likely this same known, disclosed flake — retry the page load.

## Recovery procedure if something is unavailable live

- **Camera/detector shows degraded:** the dashboard is designed to show this
  honestly (never a fabricated safe scene) — narrate it as the intended
  "honest degradation" behavior, or restart `make demo` if it's unexpected.
- **WebSocket appears stuck:** the frontend reconnect logic re-fetches a
  fresh REST snapshot on reconnect; a full page reload always recovers state
  from the backend (nothing is lost — audit/incidents persist in SQLite).
- **Simulator seems stuck:** `POST /api/v1/simulation/commands` with
  `{"command":"reset"}`, or reload `/simulation` and re-load a scenario.
- **Whole stack unresponsive:** `make demo-stop && make demo` — SQLite state
  and audit history survive the restart.
